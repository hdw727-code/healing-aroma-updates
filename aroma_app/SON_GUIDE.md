# 아로마 업무 · 1.0.1 아들 운영 안내

1.0.1용 운영 안내입니다. 이 설치본은 빈 업무 자료로 시작합니다. 설치 파일의 버전·공식 배포 안내를 확인하고 어머니 PC·본인 로그인·편집기·인쇄·백업 장치를 준비합니다. 이 문서가 공개 다운로드·설치·인터넷 업데이트의 완료를 증명하지는 않습니다. 기능은 설치본의 실제 화면과 결과를 기준으로 확인합니다.

어머니에게는 [MOTHER_GUIDE.html](MOTHER_GUIDE.html)의 견적 한 건부터 안내합니다. 설치·공식 로그인은 [SETUP_GUIDE.md](SETUP_GUIDE.md), 전체 기능은 [README.md](README.md), 실행은 [START_HERE.html](START_HERE.html)을 봅니다.

## 기기와 첫 작업

Windows 10/11 AMD64(x64: Intel/AMD 64비트) 공통 묶음입니다. Windows 10은 1809/build17763 이상이고 충분히 업데이트된 환경의 best effort 조건입니다. 두 OS 전체 실기·어머니 PC 확인을 대신하지 않습니다. macOS·32비트·ARM은 지원하지 않습니다.

검증된 설치 ZIP 전체를 새 폴더에 풀고 최상위 `INSTALL.cmd`를 실행합니다. 현재 사용자 `%LOCALAPPDATA%\HealingAromaWork`에 관리자 권한 없이 설치합니다. 공개 파일 목록·해시·런타임·신뢰 정보·빈 업무 자료를 검사하고 새 준비 폴더에서 복사한 뒤 설치 대상을 확정합니다. 기존 대상이 있으면 중단하며 덮어쓰지 않습니다. 실패한 준비 폴더는 보존하고 자동 삭제하지 않습니다.

설치 완료 뒤 바탕화면의 **아로마 업무 도우미** 또는 설치 폴더의 `aroma_app\START_APP.cmd`로 시작·종료·재실행을 확인합니다. 기존 바로가기는 보존하므로 연결 대상도 확인합니다. 설치는 앱·로그인·모델·업데이트를 실행하지 않고 서비스·전역 runtime·영구 실행 정책을 변경하지 않습니다. 컴퓨터의 프록시·계정 설정도 자동 변경하지 않습니다. 공식 실행 파일과 라이선스는 보존하고 다른 PC의 SDK·캐시·인증을 복사하지 않습니다. 시작 실패 시 OS/build·버전·오류 문구를 확인하고 보안 정책을 우회하거나 타 프로세스를 강제 종료하지 않습니다.

첫 설치의 프로그램 목록은 비어 있습니다. 사용자가 확인한 프로그램·재료·단가·세금·시간을 로컬에서 준비하고 한 건을 작성 중으로 저장해 다시 엽니다. 과거 자료를 승인 기본값으로 자동 승격하지 않습니다. 금액은 인당/공용 수량과 실제 단가를 대조합니다. 프린터/PDF·Word·PowerPoint 또는 호환 프로그램의 한글·쪽수·수치를 확인합니다.

## 자료 사본과 저장

필요한 파일만 선택해 가져옵니다. 지원 형식은 PDF·DOCX·PPTX·XLSX·XLS·HWP·HWPX·TXT·CSV·JPG·JPEG·PNG·WEBP입니다. 선택 수·개별/총용량은 화면 한도를 따릅니다. 사본 저장이지 실행·매크로·OCR·전량 분석·최신 승인 판정이 아닙니다. 원본을 이동·변경·삭제하지 않습니다.

이름이 같아도 내용이 다를 수 있습니다. 기존 사본을 조용히 덮어쓰지 않고 버전/중복 안내를 확인합니다. 저장 실패나 충돌이면 입력·이전 저장본을 남기고 상태를 확인합니다. 브라우저 임시 입력은 영구 DB·전체 ZIP과 다르므로 ‘컴퓨터에 저장됨’을 확인한 뒤 닫습니다.

## 공식 계정과 선택 AI

견적·계획·저장·로컬 서식 출력은 모델 요청 없이 작동합니다. 선택 AI 텍스트는 사용자의 본인 정상 공식 Codex 로그인과 계정 권한·사용 한도를 따릅니다. 유효한 기존 본인 로그인은 재사용하며 새 기기 코드를 자동 발급하지 않습니다. 설치/시작만으로 로그인·모델 요청을 하지 않습니다. 새 로그인이나 만료 후 재로그인은 사용자가 공식 화면에서 직접 수행합니다. 현재 로그인 파일·token·브라우저 세션을 다른 계정·기기에 복사하지 않습니다.

매 요청은 보낼 항목 선택→전체 미리보기→이번 동의→요청→실제 결과 확인 순서입니다. 전화번호·이메일 기본 제외, 파일 내용·자료 경로·사진 자동 전송 없음은 유지합니다. 직접 입력한 모든 개인정보를 자동 검출한다고 보장하지 않습니다. 고객 자료는 목적·권한·최소 범위를 확인합니다. 실패·취소 후 자동 재요청이나 유료 API 전환은 없습니다.

제목·요약·모든 본문·확인사항·주의사항을 전체 편집 화면에서 수정하고 현재 미리보기를 확인합니다. 수정 후 다시 미리보고 확인해야 합니다. PPTX는 문장 8개/8장, DOCX는 항목 3개/3쪽의 제한이 있고 길거나 구조가 맞지 않으면 원문을 유지한 채 저장을 막습니다. 원문은 로컬 기록에 유지하고 공유 파일에는 검토한 수정본만 넣습니다. 파일의 숨은 부분에 삭제한 원문을 다시 넣지 않습니다. 출력 단계의 `ai_used:false`는 추가 모델 호출이 없다는 뜻이며 AI 작성 이력과 구분합니다.

## 홍보 PNG와 선택 AI 그림

홍보 PNG는 로컬 Canvas로 글자를 배치합니다. 2480×3508픽셀 RGB이며 DPI metadata·CMYK 변환·제품 사진 자동 삽입은 없습니다. 실제 인쇄 크기·색상은 출력 장치/인쇄소에서 확인합니다. PNG는 앱에 먼저 저장하고 확인된 서버 URL로 다운로드하며 전체 업무 백업에 들어갑니다. 저장 응답을 확인하지 못하면 입력을 유지하고 상태를 조회합니다.

AI 그림은 **연결·관리 → 이미지 요청 준비**에서 새 그림 한 장의 설명을 적습니다. **보낼 내용 미리보기 → 이번 전송 동의 → 이번 이미지 요청하기**를 거치며 완료 후 **PNG 이미지 내려받기**로 받습니다. 앱은 PNG를 검사해 작업 결과 폴더에 저장하고 미리보기·다운로드를 제공합니다. 이 파일은 전체 업무 백업 v2에도 포함합니다. 참고 사진 업로드·기존 이미지 수정·여러 장 생성은 지원하지 않습니다.

AI 그림 파일은 문서·발표자료·홍보물에 자동으로 넣지 않습니다. 받은 그림을 편집 프로그램에서 직접 사용하고 실제 파일의 그림·본문·사용 권리를 확인합니다. 그림 크기·투명 배경 등 결과는 요청마다 확인합니다. Codex 전용 저장소에도 그림 사본이 남을 수 있으며 로그인 저장소 전체는 업무 백업에 넣지 않습니다.

로그인은 앱 전용 환경의 본인 공식 계정과 운영체제 keyring 저장소를 사용합니다. 저장소를 사용할 수 없으면 평문 파일로 자동 전환하지 않습니다. 유효한 기존 본인 로그인은 재사용하며 새 기기 코드·모델 요청을 자동 실행하지 않습니다. 로그인·준비 표시만으로 이번 생성의 성공을 보장하지 않습니다. 실제 결과 파일을 확인하고 실패·취소 후에는 상태를 먼저 확인합니다. 자동 재시도와 유료 API 전환은 없으며 실패한 요청도 계정 사용량을 소모할 수 있습니다.

## 전체 백업 v2와 복구

| 대상 | 새 전체 업무 백업 |
|---|---|
| 문서·연락처·이력·설정·자료 목록·AI 작업 상태 | DB의 일관된 사본 |
| 가져온 실제 사본·AI 글/그림 결과·앱 출력물/PNG | 실제 파일 포함 |
| 현재 `catalog.json` 프로그램·`files.json` 자료 목록 | 현재 바이트와 파일 부재 상태 포함 |
| 관리자 PIN·현재 세션·Codex 로그인·인증 | 제외. 복구 때 현재 PC의 PIN은 유지 |
| 로그·이전 백업·이전 콘텐츠 사본·실제 서식 파일·앱 코드 | 제외·필요하면 별도 보관 |
| 원본·앱 밖에만 있는 다운로드·브라우저 임시 입력 | 제외·별도 보관 |

v2는 현재 프로그램/자료 목록까지 백업 시점으로 복구합니다. v1 전체 백업은 현재 두 설정 파일을 유지합니다. 예전 ‘문서·설정 백업’은 실제 파일 사본을 포함하지 않습니다. 목록의 형식·포함 표시를 확인하며 이전 앱은 v2를 읽지 못할 수 있습니다. 기본 압축 전 한도는 1 GiB·10,000개이고 한도 초과·미지원 파일은 몰래 빼거나 줄이지 않습니다.

작업 저장→AI 종료/취소 확인→전체 백업 만들기→ZIP 다운로드→독립 저장장치 복사 순서로 보관합니다. 같은 디스크의 ZIP은 고장 대비 백업이 아닙니다. 고객 정보가 있을 수 있어 공개 저장소·설치 파일·업데이트 파일에 넣지 않습니다. 공유용 ZIP에는 PIN salt/hash를 남기지 않습니다. 복구 전 로컬 보존 자료는 비공개로 관리합니다.

다른 저장장치에 보관한 ZIP을 복구할 때는 관리자가 **화면에 표시된 현재 백업 위치**로 파일 이름을 바꾸지 않고 복사한 뒤 목록을 새로 봅니다. 복구용 ZIP 업로드 화면은 없습니다. 업데이트 후 자료 위치가 바뀔 수 있으므로 예전 폴더를 고정 경로로 사용하지 않습니다. 목록에 나타나지 않거나 확인에 실패하면 임의로 DB를 고치지 않습니다.

복구는 서버 목록의 백업 선택·현재 관리자 PIN·직접 확인을 요구합니다. 먼저 전체 안전 백업과 이전 자료를 남기고 DB/사본/AI/출력/설정을 같은 시점으로 바꿉니다. 완료 응답 뒤 실제 문서 수·금액·사본·출력을 비교합니다. PIN은 현재 PC에서 앱 재실행과 복구 뒤에도 현재 값을 유지하고 로그인 정보는 복원하지 않습니다.

응답 유실·중단이면 성공을 단정하거나 같은 복구를 자동 반복하지 않습니다. 상태 조회와 작업 잠금을 유지하고 종료 확인 뒤 재시작합니다. 중단 복구는 PIN과 직접 확인 후 안전 백업으로 돌아갑니다. 알 수 없는 잠금은 이전 실행의 종료를 확인하기 전 지우거나 모르는 프로세스를 종료하지 않습니다. 실패한 자료·안전 백업도 보존합니다.

## 서명 업데이트와 공개 범위

[공식 저장소](https://github.com/hdw727-code/healing-aroma-updates)의 실제 릴리스와 앱의 다운로드·서명 검사 결과를 확인합니다. 저장소가 있다고 업데이트 파일이 존재하는 것은 아닙니다. 적용 전에 전체 업무 백업을 보관하고 업데이트 확인→변경 내용 확인→로컬 PIN→이번 적용 확인→실제 서버 상태 확인 순서로 사용합니다. 응답이 끊기면 요청 상태를 조회하고 자동 재적용하지 않습니다. 이 절차 설명이 특정 공개 릴리스의 실제 적용 완료를 뜻하지는 않습니다.

고정 공개키와 서명 manifest·해시·버전·허용 파일·DB 구조를 검사합니다. 다운로드한 manifest 안의 키로 신뢰키를 바꾸지 않습니다. 고정 검증키 파일은 `frozen_update/TRUSTED_PUBLISHER.json`입니다. 자기 앱의 종료와 작업자 종료를 확인한 뒤 옆 폴더의 새 코드와 사용자 데이터 사본을 시험합니다. 성공 시에만 새 버전을 선택하고 실패하면 이전 코드와 읽을 수 있는 이전 데이터를 함께 사용합니다. 새 실패 사본은 보존합니다. 지원하지 않는 DB 구조 변환은 거부합니다.

업데이트 code slot과 사용자 자료·수정 프로그램·비공개 로그인 저장 위치는 분리합니다. 원격 다운로드는 공개 코드·범용 빈 서식·공식 runtime·공개검증 정보만 대상으로 합니다. 고객·원본·업무 색인·실제 프로그램/단가·DB·사본·AI 결과·출력·백업·로그인·개인키를 공개하지 않습니다. 로컬 업무 HTTP 서버를 인터넷에 노출하지 않습니다. PIN은 로컬 권한 확인이며 원격 계정 인증을 대신하지 않습니다.

발행용 개인키는 업무 ZIP·설치본에 넣지 않습니다. 같은 Windows 사용자에 의존하는 암호화 사본의 hash 일치와 실제 복원 가능성은 다릅니다. 키/원래 프로필을 잃으면 서명을 중단하고 별도로 확인한 새 공개키의 설치본으로 수동 재설치·신뢰 교체합니다. 잃은 키로 새 키를 자동 승인한다고 설명하지 않습니다.

## 비용과 인수

선택 AI는 본인 계정의 플랜 사용량·한도를 사용합니다. 실행 도구 라이선스가 모델 무료 사용을 뜻하지 않습니다. 취소·오류 시 사용량 복원·무제한 무료·일정 비용을 보장하지 않습니다. 로컬 계산·서식 출력은 추가 모델 호출이 없지만 편집기·프린터·백업 장치와 이후 선택 서비스 비용은 별도입니다. 유료 API·새 서버·새 권한은 자동 신청하지 않습니다.

완료 기준은 사용자가 직접 견적을 저장·다시 열고 실제 출력물을 확인하며, 독립 장치의 전체 ZIP을 복구해 문서·사본·AI·PNG·수정 프로그램을 확인하는 것입니다. 설치·계정·이미지·공개 릴리스·원격 업데이트는 각각 실제 근거가 있을 때 완료로 기록합니다. 절감 시간·매출·오류 제거 수치는 약속하지 않습니다.
